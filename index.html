01 / The process

Start small. Make it useful.

You don't need to be an expert or write code to contribute. Good documentation, bug reports, and thoughtful feedback all count.

STEP 01⌕

Find a place to help

Look through the project's issues for a bug, improvement, or a task marked “good first issue.” Not sure? Ask before starting.

STEP 02⑂

Set up your copy

Fork the repository to your GitHub account, clone your fork, and create a branch for one focused change.

STEP 03✳

Build and check

Make the change, run the relevant checks, and keep your commit message short and specific.

STEP 04↗

Share a pull request

Push your branch and open a PR against the project's main branch. Explain what changed and why.

STEP 05↺

Respond to feedback

Reviewers may ask questions or suggest edits. Talk it through, make updates on the same branch, and push again.

STEP 06✓

Celebrate the merge

Once approved and merged, your contribution is part of the project. Thanks for making it better.

02 / A simple Git workflow

From fork to pull request.

Replace YOUR-USERNAME and REPO with your fork's details. Run these commands from your terminal.

One branch = one focused change
Clone your fork01 — SET UP
git clone https://github.com/YOUR-USERNAME/REPO.git
Create a branch02 — ISOLATE
git switch -c fix/describe-your-change
Save your work03 — COMMIT
git add . && git commit -m "Describe your change"
Push your branch04 — SHARE
git push -u origin fix/describe-your-change
03 / Before you submit

A good PR is easy to review.

Keep the change focused, describe the outcome, and give reviewers enough context to understand your thinking.

✓Explain the problem your change solves
✓Link the related issue, if there is one
✓Run relevant tests or checks
✓Add screenshots for visible UI changes
✓Keep unrelated changes out of the PR
✓Be kind and open to discussion

Open source is built by people, together.

Be respectful. See Contributor Covenant for a community code of conduct.
